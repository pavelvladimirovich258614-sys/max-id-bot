# MAX Group Export — отдельный плагин Hermes Agent

Плагин добавляет две **slash-команды** к уже установленному MAX-адаптеру
[Realmagnum/hermes-max-integration](https://github.com/Realmagnum/hermes-max-integration).
Это **не** второй MAX-бот: новый процесс polling/webhook не запускается, токен
`MAX_BOT_TOKEN` используется от действующего бота Hermes. Существующий бот
из корня репозитория (`bot.py`, `BOT_TOKEN`) не затрагивается.

## Реальная поддержка MAX API

- `GET /me`: ID бота.
- `GET /chats/{chatId}`: сведения о чате/канале по известному числовому ID.
- `GET /chats/{chatId}/members/me`: права бота.
- `GET /chats/{chatId}/members?user_ids=...`: права запрашивающего.
- `GET /chats/{chatId}/members?count=100&marker=...`: участники постранично;
  бот **должен быть администратором**.
- `POST /uploads?type=file` → загрузка на доверенный CDN →
  `POST /messages`: отправка CSV.

Список участников по этому методу **не содержит номеров телефонов**.
Никакие телефоны не собираются, не обогащаются и не подставляются.
`ids`: только `user_id`.
`full`: `user_id,first_name,last_name,username,is_bot` (только поля из MAX).

Документация:
- https://dev.max.ru/docs-api/methods/GET/chats/-chatId-/members
- https://dev.max.ru/docs-api/methods/GET/chats/-chatId-/members/me
- https://dev.max.ru/docs-api/methods/POST/uploads/
- https://dev.max.ru/docs-api/methods/POST/messages

## Установка в Windows Hermes (без изменения действующего бота)

Откройте PowerShell в клоне репозитория:

```powershell
$hermes = "$env:LOCALAPPDATA\hermes\bin\hermes.exe"
$target = "$env:LOCALAPPDATA\hermes\plugins\max-group-export"
Copy-Item -Recurse -Force .\hermes_plugin\max_group_export $target
& $hermes plugins enable max-group-export
```

Для применения нового обработчика обычно потребуется перезапуск Gateway.
**Не перезапускайте его без согласования**, если идут активные сессии.
`MAX_BOT_TOKEN` в активном `.env` Hermes должен быть уже настроен
через `hermes gateway setup`. Используйте одно и то же активное окружение.

В активном `.env` Hermes задайте:

```dotenv
MAX_ALLOWED_USERS=OWNER_MAX_USER_ID
MAX_ALLOW_ALL_USERS=false
MAX_EXPORT_OWNER_IDS=OWNER_MAX_USER_ID
MAX_EXPORT_CHAT_IDS=-1234567890
MAX_EXPORT_MAX_MEMBERS=5000
MAX_GROUP_POLICY=allowlist
MAX_GROUP_ALLOWED_USERS=OWNER_MAX_USER_ID
MAX_GROUP_ALLOWED_CHATS=-1234567890
```

`OWNER_MAX_USER_ID` — пример уже известного MAX ID владельца. `-1234567890` —
**пример**, замените фактическим числовым ID вашего чата/канала.
При смене конфигурации Gateway должен загрузить новые переменные.
Пустые `MAX_EXPORT_OWNER_IDS` или `MAX_EXPORT_CHAT_IDS` запрещают выгрузку.

Не указывайте `MAX_ALLOW_ALL_USERS=true`. Не публикуйте API-токены.
Переменные `MAX_GROUP_ALLOWED_CHATS` и `MAX_GROUP_ALLOWED_USERS` относятся
к **существующему адаптеру** `max-platform`; при политике `allowlist`
должны быть заполнены подходящими значениями, иначе сообщения из групп
не попадут в Hermes.

## Команды в MAX

В личном чате с Hermes:
- `/maxid` — ваш User ID и ID самого бота.
- `/maxid -1234567890` — ID и информация о заранее разрешённом чате/канале,
  если запрашивающий — его администратор.
- `/maxexport -1234567890 ids` — CSV только с ID.
- `/maxexport -1234567890 full` — CSV с доступными полями участников.
  Файл приходит **лично запрашивающему**, не в произвольный чат.

В разрешённой группе MAX:
- `/maxid` — ID текущей группы и бота.
- `/maxexport ids` или `/maxexport full` — отправка CSV **в эту же группу**
  только по явной команде владельца и администратора группы.

Для канала без командного ввода используйте **личный чат с числовым ID канала**,
полученным из события добавления бота, пересланного сообщения или другого
официального метода MAX API. Плагин не угадывает ID по внешним ссылкам.

Нативный MAX-адаптер Hermes уже принимает событие `bot_added`.
**Автоматического массового экспорта при добавлении бота нет**: только после
явной команды доверенного администратора. Это защищает участников и исключает
неожиданную публикацию документа. Отдельный `bot.py` этого репозитория уже
обрабатывает `bot_added` для своего независимого MAX-бота.

## Ограничения и диагностика

- Экспорт возможен только для группы/канала, где бот имеет права администратора
  и сам запрашивающий пользователь — администратор или владелец.
- Пагинация до 100 записей за запрос; повторяющиеся ID удаляются, зацикленный
  `marker`, неполные ответы и превышение лимита прерывают выгрузку без файла.
- Режим `full` содержит имена и никнеймы только при их наличии.
- MAX API не предоставляет официальный список всех чатов бота через `GET /chats`;
  сохраните числовой ID из сообщения/события.
- Экспорт временно существует только в памяти; постоянная база участников не ведётся.
  CSV передаётся в MAX и остаётся там по правилам мессенджера.
- Параметры подписи, обработка файлов MAX и наличие прав проверяются на живом
  боте отдельно; тесты здесь используют только фейковые HTTP-ответы.
- На Windows может потребоваться системный сертификат Минцифры для MAX API.
- `/maxexport` может получить ошибки 403/429 и `attachment.not.ready`,
  которые требуют диагностики и/или повторной отправки.
- **Не используйте CSV для нежелательных массовых сообщений.** Перед выгрузкой
  убедитесь, что участники и администраторы согласовали обработку данных.

## Тесты

Из корня клона, без токена MAX и без отправки сообщений:

```bash
python -m unittest discover -s tests -p "test_hermes_max_group_export.py" -v
```

Перед деплоем проверьте путь активного профиля, доступность команды в MAX,
реальную доставку небольшого CSV и работу API; это отдельная live-проверка.
